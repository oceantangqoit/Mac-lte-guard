# 语言包翻译准则 / Translation Policy

本文件规定 LTE Guard 语言包（`lang/*.ini`，72 个文件 × 186 条）的翻译边界，
用于保证各语言之间的**一致性**：同一类文本在所有语言里的处理方式必须相同。

**原意以简体中文（`zh-Hans.ini`）为准**，英文（`en.ini`）为第二参考。

---

## 一、必须保持原样，不得翻译

| 键 | 内容 | 理由 |
|---|---|---|
| 1 | `LTE Guard` | 产品名，全球唯一标识 |
| 57 | `MIT`（协议名部分） | 开源许可证的法定名称 |
| 65 | `maclteguard@tanghaiyang.cn` | 电子邮件地址 |
| 120 | 企业微信 / 钉钉 → WeCom / DingTalk | 平台官方外文名 |
| 121 | 飞书 → Feishu (Lark) | 平台官方外文名 |
| — | `Webhook`、`USB`、`App`、`Mac`、`macOS`、`Gatekeeper`、`shell`、`proxy`、`{0}` 占位符、`usbreset`、`updates`、`.ini` | 技术标识符与系统术语 |

作者署名（键 64）中的 `Ocean Tang` 与项目地址保持拉丁字母原样；
姓名的本地文字转写可以附加，但不得替换。

## 二、必须完整本地化

除上表以外的全部文本，包括：

- 菜单项、按钮、对话框正文
- 日志与通知文案
- 协议、免责声明、权限说明等长文
- 系统路径提示中的**描述性文字**（路径本身保持原样）

不得留英文兜底。审查脚本以「该语言的值与 `en.ini` 逐字相同且长度 > 12 字符」
判定为兜底，白名单见第一节。

## 三、汉语方言文件的特殊规则

方言文件（`yue` `nan` `nan-chaoshan` `hak` `hsn` `wuu` `wuu-shanghai`
`cmn-sichuan` `cmn-dongbei` `cmn-henan` `cmn-shaanxi` `cmn-xinjiang` `lzh`）
应当用**当地口语**改写，而非照抄普通话。但以下几类**有意与普通话保持一致**，
不属于漏译：

1. **正式称谓** —— 键 182「中国少数民族语言」。民族称谓采用国家标准表述，
   任何方言化改写都可能造成不尊重，一律统一。
2. **法律文书名称** —— 键 136「门卫室拍照功能使用协议」、键 135「签约存档」。
   协议名称是签署行为指向的对象，必须在所有中文变体里字面相同。
3. **产品与技术术语** —— 键 56「关于 LTE Guard」、75「重置 USB 设备」、
   88「重新挂载」、89「重连」、90「重启」，以及键 67/68「打开语言文件夹…」
   「打开配置文件夹」。这类「动词＋系统对象」短语在各汉语方言里的口语说法
   与普通话本就一致，刻意改写反而拗口。
4. **日志格式行** —— 键 99、101、112、113、165、173、177、191 等。
   日志需要跨语言可比对，保留统一措辞。
5. **作者署名** —— 键 64。

繁体方言（`yue` `nan` `nan-chaoshan` `hak`）使用繁体字；
`wuu` `wuu-shanghai` 及各官话方言使用简体字。

## 四、语言名称（`[meta] name=`）的写法

外语一律采用「**当地语言（中文名）**」格式，例如：

```
name=Русский（俄语）
name=العربية（العربية اللغة）   ← RTL 语言的中文名同样按 RTL 规律书写
```

汉语方言直接写中文名（`四川话`、`上海话`）。
朝鲜／韩国语按使用地区分列三份：`ko`（韩国）、`ko-KP`（朝鲜）、`ko-CN`（朝鲜族）。

## 五、从右向左书写的语言

`ar` `fa` `he` `ur` `ug` `lzh` 等 RTL 语言：

（`lzh` 文言依传统右起之制列入；行内汉字仍左起，见下条。）

- 文本按 Unicode 双向算法自然排布，**不做字符级反转**
- 占位符 `{0}` 周围如需隔离，使用 FSI (U+2068) / PDI (U+2069)
- 菜单整体方向由程序在切换语言时设置应用级 `NSForceRightToLeftWritingDirection`
  并**自动重启**生效（不弹确认框——重启是实现手段，不是用户要做的决定），
  语言文件本身不承担这一职责

## 六、翻译署名与责任

每个文件的 `author=` 行标注「翻译由 AI 辅助 / AI-assisted translation」。
用户通过「编辑当前语言…」导出后，程序会抹去原作者署名并换成使用者姓名——
自此该文件的内容责任转移给使用者。键 74 的协议正文即为此约定，
所有语言必须完整传达这一含义，不得简省。

## 七、审查脚本

```bash
python3 tools/check-lang.py     # 结构、占位符、英文兜底、方言本地化四项
```

四项检查的判定口径与本文件一致；新增键时同步更新白名单。

## 八、条目作废的处理

界面改版后不再使用的条目（如键 192、193 原为切换书写方向的重启确认框，
改为自动重启后不再引用）**保留在所有语言文件中，只是代码不再引用**。
不删除、不改编号——将来若恢复该界面，译文原地可用。
