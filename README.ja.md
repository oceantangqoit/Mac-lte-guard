## 問題

多くの USB LTE モデムや USB 有線 LAN アダプタは、Mac を閉じてスリープさせた後に「フリーズ」します。ランプは点いたまま、システム上にもインターフェースが見えているのに通信できず、**一度抜いて挿し直すまで復旧しません**。

原因は、スリープ中も macOS が USB 給電を切らない（VBUS は SMC ファームウェアが直接管理し、公開 API からは制御できない）一方で、デバイス側の USB セッションはすでに失われているためです。ネットワークサービスを再起動しても直らないのは、リセットすべき対象が USB 層だからです。

## こんな方に

Mac が **USB 外付けネットワークアダプタ**でインターネットに接続していれば、誰でも遭遇しうる問題です。

- 🚁 **ドローンの映像伝送を LTE 化した構成** —— DJI 初代の映像伝送機をセルラー回線に改造する遊びなど、Mac 側に 4G/5G モデムを挿したまま長時間待機する用途
- 📡 **USB LTE / 4G / 5G モデム、モバイルルーター、USB セルラーモジュール** —— 屋外作業、車載、船上、展示会、仮設オフィス
- 🔌 **USB-C / Thunderbolt 有線 LAN アダプタ** —— Mac には LAN ポートがないため、会議室・サーバールーム・客先で LAN ケーブルを使う場面
- 🧩 **ドックに内蔵された LAN ポート** —— Belkin、Plugable、Anker、CalDigit など
- 🎥 **安定した上り回線が必要なライブ配信・RTMP 配信・リモート運用**
- 🖥 **ソフトルーター / Raspberry Pi / 産業機器**を USB LAN 経由で Mac に直結してデバッグする場合

共通点は同じです。一度閉じて開くと通信が途絶え、ランプは点いているのに **抜き差ししないと戻らない**。

### ネットワークアダプタだけではありません

「復帰後にフリーズし、物理的な抜き差しでしか直らない」という同じ現象は、他の USB 機器でも頻繁に報告されています。[Apple 公式コミュニティ](https://discussions.apple.com/thread/7745583)、[MacRumors](https://forums.macrumors.com/threads/mac-mini-m1-usb-ports-not-working-after-wake-from-sleep.2326616/)、[Plugable ナレッジベース](https://kb.plugable.com/docking-stations-and-video/devices-are-not-detected-after-waking-from-sleep-or-after-rebooting-on-macos)には、オーディオインターフェース、ウェブカメラ、外付けドライブ、カードリーダー、ドック内の各コンポーネントに関する報告が数多く集まっています。

仕組みが同じであるため、本ツールのメニューには **「USB デバイスをリセット」** を用意しました。接続中の USB 機器を一覧表示し、選んだ機器に対してソフト的な抜き差しを実行します。手を伸ばしてケーブルを抜く必要はありません。なお、ネットワークアダプタ以外は手動操作となります（自動検知はネットワークのみ対応です。「通信できるかどうか」は明確に判定できますが、ウェブカメラやオーディオインターフェースがフリーズしているかを確実に判定するのは困難なためです）。

> ⚠️ 外付けドライブなどのストレージに使う前に、読み書きを止めて取り出しを済ませてください。データ破損の恐れがあります。

### よく案内される「公式の対処法」が効かない理由

| よく勧められる方法 | この症状に効かない理由 |
|---|---|
| SMC / NVRAM リセット | Apple Silicon 機には**そもそも SMC リセットが存在しません**。Intel 機で実行しても、次に蓋を閉じれば再発します。原因に対処していないためです |
| 「ネットワークアクセスによるスリープ解除」を無効化 | この設定は「スリープ中にネットワーク経由で起こされる」動作を制御するもので、復帰後に USB セッションが失われる問題とは別物です |
| 完全にシャットダウンして再起動 / macOS を更新 | 効きますが現実的ではありません。蓋を閉じるたびに再起動するのでしょうか |
| アダプタではなく LAN ケーブルを抜く | フォーラムで繰り返し勧められますが、実際には効きません（元の投稿者本人が「それも試したが駄目だった」と回答しています） |
| **USB アダプタを抜いて挿し直す** | 唯一確実に効く方法です —— **本ツールはこれをソフトウェアで自動化します** |

## 仕組み

LTE Guard はメニューバーに常駐し、システムの復帰イベントを監視します。復帰後は**即座に**、IOKit（`USBDeviceReEnumerate`）を用いて対象の USB デバイスに **ソフトウェア的な抜き差し** を実行します——物理的な抜き差しと等価です。「修復すべきかどうか」の事前チェックは一切行いません。このツールを入れた時点で、あなたはフリーズ被害の当事者であり、チェックは時間の無駄でしかないからです。復旧と判定するのは、**ゲートウェイに実際に ping が通ったとき**だけ。所要は**通常 8 秒ほど**で、手で抜き差しする物理的な限界に迫る速さです。

- 🎯 **メーカーを問いません** — 選択時に VID/PID を自動検出するため、内蔵のデバイスリストはありません
- 🖇 **複数のアダプタを同時に見守れます** — チェックを入れるだけで何枚でも。各アダプタは独立に検知され、並行して修復されます
- 🔌 **USB 以外のアダプタにも対応** — ネットワークサービスの再起動に自動でフォールバックします
- 🛠 **2 段階のコマンドフック** — **切断を検知した瞬間**に実行する組（例：ネットワークパネルを開いて修復の一部始終をその場で眺める）と、**復旧後**に実行する組（プロキシの再接続、再ダイヤルなど）
- 🔔 **通知は成功時だけ** — アダプタが復旧し、*かつ*実際にインターネットへ出られることを確認できたときに、所要時間つきで一度だけ通知します。修復中・外部不通・失敗はメニューバーのアイコンだけで表現します（スピナー / `✓8s` / `⚠︎` / `✕`）
- 🌍 **62 言語** — UI もログも完全ローカライズ。システム言語に自動追従し、メニューから切り替えも可能
- 🪶 **依存ゼロ** — アプリ 1 つだけ。常駐デーモンのインストールも Homebrew も不要で、一切の特権も要りません

## インストール

**方法 1：配布パッケージを使う**（[Releases](../../releases)）

- `LTEGuard-x.y.z.dmg` — 「アプリケーション」にドラッグ
- `LTEGuard-x.y.z.pkg` — ダブルクリックでインストール。ログイン時の自動起動も設定されます

初回起動時に「開発元を検証できません」と表示された場合（未署名アプリでは通常の挙動です）：**アプリを右クリック → 開く → 開く**、またはターミナルで次を実行してください。

```bash
xattr -dr com.apple.quarantine /Applications/LTEGuard.app
```

**方法 2：自分でビルドする**（Xcode コマンドラインツールが必要）

```bash
git clone https://github.com/oceantangqoit/Mac-lte-guard.git
cd Mac-lte-guard && ./build.sh
```

成果物は `dist/` に出力されます。アイコンの生成には `brew install librsvg` が必要ですが、無くてもビルドは通ります（既定アイコンになります）。

## 初回起動

インストール後に最初に開くと、案内が表示されます：**説明 → 見守る対象のアダプタを選択 → 自動起動の可否を確認**。順にクリックするだけです。

うまくいかないときは、まずメニューの **診断を実行** をお試しください。項目ごとに点検し、対処法をそのまま示します。

| 診断項目 | 問題がある場合の意味と対処 |
|---|---|
| インストール場所 | `/Volumes/…` と表示される場合は DMG から直接実行しています。まずアプリを「アプリケーション」にドラッグしてください |
| 隔離属性 (Gatekeeper) | 未署名アプリでは通常の状態です。開けない場合は **アプリを右クリック → 開く → 開く**、または `xattr -dr com.apple.quarantine /Applications/LTEGuard.app` |
| 修復ツール | usbreset が利用可能かどうか。通常はアプリに同梱されており、個別のインストールは不要です |
| 見守る対象 | アダプタが選択済みか、そのインターフェースが実在するか（アダプタを交換した場合は警告されます） |
| ログイン時に起動 | オフの場合、再起動後は自動実行されません。メニューからいつでも切り替えられます |

**権限について**：本ツールは**一切の特権を必要としません**。アクセシビリティもフルディスクアクセスも root も不要で、常駐デーモンもインストールしません。

## 使い方

1. 起動するとメニューバーにアイコンが表示されます
2. メニュー → **対象を選択…** → お使いのアダプタを選びます——**複数選択できます**（`· USB` 付きの項目はソフト抜き差しに対応）
3. 以上です。次からは蓋を閉じて開いても、切れていれば自動で直ります

メニューのその他の項目：

| 項目 | 説明 |
|---|---|
| 今すぐ検査して修復 | 手動で一度実行します |
| ログを表示 | `~/Library/Application Support/LTE Guard/lte-guard.log` を開きます |

## 右から左に書く言語（RTL）

右から左に書く言語を 4 つ内蔵しています：**العربية**（アラビア語）、**עברית**（ヘブライ語）、**فارسی**（ペルシア語）、**اردو**（ウルドゥー語）。

本ツールの言語切り替えは macOS の `.lproj` ローカライズ機構ではなくアプリ内で独自に実装している（`lang/*.ini` を読む）ため、システム側は画面を自動でミラーリングしません。そこで次の対応を入れています。

1. **レイアウトのミラーリング** —— RTL 言語に切り替えると、メニューとサブメニューを `.rightToLeft` に設定します。テキストは右揃え、アイコンは右側、サブメニューの矢印も反転します。
2. **双方向テキストの隔離** —— 文言に差し込む値（インターフェース名 `en2`、`2c7c:0125`、サービス名など）はラテン文字と数字です。これをアラビア語の文にそのまま埋め込むと Unicode の双方向アルゴリズムによって並び替えられ、**コロンや括弧が反対側に移動してしまいます**。そのため、すべてのプレースホルダー置換で `U+2068 FSI` / `U+2069 PDI` によって囲み（W3C i18n の推奨手法）、差し込む値それぞれを独立した方向単位にしています。
3. 「復旧後に実行するコマンド」の入力欄は左揃えを強制しています。シェルコマンドは常にラテン文字であり、右揃えではかえって読みにくいためです。

## 多言語対応

**62 言語**を内蔵し、起動時にシステム言語へ自動追従します。メニューの「言語」から手動で切り替えることもできます（選択は記憶されます）。

後から追加された言語は AI 支援による翻訳で、母語話者の校閲を経ていないものがあります（ファイル冒頭に明記しています）。**表現が不自然だと感じたら、1 行だけ直して Pull Request を送っていただけると助かります** —— 最も気軽に貢献できる方法です。

**既存の言語の文言を直したい場合**：メニュー「言語 → 現在の言語を編集…」を選ぶと、その言語の ini が**アプリ内からご自身の言語フォルダにコピーされ、そのまま開きます**。編集後にアプリを再起動すれば反映されます。このコピーは内蔵版より優先されるため、**アプリを更新しても上書きされません**。

書き出しの際には確認ダイアログが表示され、次の処理が行われます：**元の作者名と連絡先を削除し、あなたの名前に置き換える**。つまり書き出した時点でこのファイルはあなた自身のものとなり、その内容についてはあなたが責任を負い、元の作者とは無関係になります。違法な内容、他者を侮辱する内容、他者の権利を侵害する内容は書き込まないでください。編集したファイルはお使いのコンピュータ内にのみ保存され、自動的にアップロードされることはありません。

**新しい言語を追加する場合**：メニュー「言語 → 言語フォルダを開く…」（`zhs.template.ini` 簡体字中国語と `en.template.ini` 英語の 2 つのテンプレートが自動的に置かれます）。いずれかを複製して目的の言語コード（例：`nl.ini`）に改名し、各行の等号の右側を翻訳するだけです。

言語ファイルの探索順序は **あなたの言語フォルダ → アプリ内蔵** です。同名ファイルはあなたのものが優先されます。仕上がったファイルはぜひ Pull Request でお寄せください。同じ言語を使う方々の役に立ちます。

**言語ファイルの形式**：1 言語につき 1 つの INI ファイルを `lang/` ディレクトリに置き、数値をキーとして使います。

```ini
[meta]
name=日本語
author=……

[strings]
1=LTE Guard
2=監視中：{0}  {1}
3=● 正常
```

`{0}` `{1}` はプレースホルダーで、アプリが値を差し込みます。

## 設定ファイル

`~/Library/Application Support/LTE Guard/lte-guard.conf`（アプリが自動管理しますが、手動編集も可能です。旧版の単一対象の設定は自動的に引き継がれます）:

```sh
# 1 行につき 1 つの見守り対象。タブ区切り：インターフェース、サービス名、USB_VID、USB_PID
TARGETS='en2	My LTE	2c7c	0125'
PRE_CMD=''             # 切断を検知した瞬間に実行（この時点でネットワークは不通——あてにしないこと）
POST_CMD=''            # 復旧後に実行（例：プロキシの再起動）
```

**どちらのフックも複数のコマンドに対応**しています——1 行に 1 つ、上から順に実行されます。`PRE_CMD` は検知の**瞬間**に走るため、ここでネットワークパネルを開くようにしておけば、ちょうど間に合って修復の一部始終を眺められます。

ダイアログには 2 つのグループに分かれたチェック項目があり、チェックを入れると対応する入力欄に即座に書き込まれ、外すと削除されます。

**よく使う項目**（常に表示）

- システム設定 → ネットワークを開く（切断時の欄に入ります）——切れた接続が戻ってくる様子を自分の目で確かめられます
- サウンドを再生
- Webhook 通知を送信（プレースホルダーの URL をご自身のものに置き換えてください。無人運用のマシンに便利です）

復旧通知とインターネット疎通チェックは**内蔵**です——チェックを入れる必要はありません。修復後、アプリはそのアダプタ経由で実際に外部への接続を確かめ、本当につながったときにだけ、所要秒数つきで通知します。インターフェースは復旧したのに外に出られない場合は `⚠︎`、失敗した場合は `✕` をアイコンだけで表示し、しつこく通知することはありません。

例——切断時にネットワークパネルを開き、復旧後にプロキシを再起動してサウンドを鳴らす場合:

```sh
PRE_CMD='open "x-apple.systempreferences:com.apple.Network-Settings.extension"'
POST_CMD='launchctl kickstart -k gui/$(id -u)/com.user.gost-lte\nafplay /System/Library/Sounds/Glass.aiff'
```

設定ファイル内では、改行は `\n`、シングルクォートは `\'` と書きます（アプリが自動でエスケープします。手動編集の際も同じ形式に従ってください）。

## 動作の流れ

```
システム復帰（IORegisterForSystemPower + NSWorkspace の二重待ち受け）
      ↓  即座に PRE_CMD を実行（例：ネットワークパネルを開く）。USB の通電を 1 秒待つ
USBDeviceReEnumerate              → USB 以外なら networksetup でサービス再起動
      ↓  事前チェックなし——このツールを入れた時点でフリーズ被害の当事者だから
毎秒ポーリング：ゲートウェイに ping が通ってはじめて復旧と判定（見かけだけの IP では ping は欺けない）
      ↓  復旧
POST_CMD を実行 → そのアダプタ経由で外部接続を実測 → 本当につながったときだけ通知（所要時間つき）
      ↓
アイコンがすべてを物語る：スピナー = 修復中、✓8s = 完了、⚠︎ = 外部不通、✕ = 失敗
```

複数のアダプタはそれぞれ独立に、並行して修復されます。15 秒のクールダウンは、二重の待ち受けから届く重複した復帰シグナルを吸収するためだけのものです。

## 互換性と検証状況

### 検証済みで動作を確認

| 項目 | 環境 |
|---|---|
| 機種 | MacBook（Apple Silicon、arm64） |
| OS | macOS 26（Darwin 25.x） |
| アダプタ | Quectel EC25（VID `2c7c` / PID `0125`）、ECM/NCM モードで `enX` として認識 |
| シナリオ | 蓋を閉じてスリープ → 復帰後インターフェースは存在するがゲートウェイに到達不可 → ソフト抜き差しで **約 8 秒で復旧**。何度も再現を確認 |
| 追加 | 復旧後に、そのインターフェースへ紐づけたプロキシを `POST_CMD` で再起動 |

### 原理上は動作するはずだが、実機での報告を求めている構成

| ケース | 想定される挙動と必要な調整 |
|---|---|
| **Intel Mac** | 一部の Intel 機では `USBDeviceReEnumerate` に root 権限が必要で、ログに `open failed … try sudo` が出ます。対処：一度 `sudo` で実行して確認するか、設定の `USB_VID` を空にしてネットワークサービス再起動方式に切り替えてください |
| **macOS 13 / 14 / 15** | 使用している API（IOKit 電源通知、`USBDeviceReEnumerate`、`NSStatusItem.isVisible`）はいずれも 13 以降で安定しており、問題なく動作する見込みです。13 未満では起動しません（Info.plist で制限） |
| **USB 有線 LAN アダプタ**（AX88179、RTL8153、CM3xx など） | 仕組みは同じで動作するはずです。ただし機種によっては再列挙後にインターフェース名が変わることがあります（`en5`→`en6`）。その場合はメニューから「対象を選択」をやり直してください |
| **ダイヤルアップ型 4G モジュール**（ECM/NCM ではなく PPP/AT 方式） | 再列挙後に再ダイヤルしないと IP が得られず、60 秒の待機後に失敗と判定されます。対処：「復旧後に実行するコマンド」に再接続用のコマンドを設定してください |
| **ドック内蔵の LAN ポート** | 再列挙の対象がドック全体の USB デバイスである場合、ドックに接続した他の機器（外付けドライブ、カメラ）も一緒にリセットされます。書き込み中のドライブがある場合は、サービス再起動方式をお勧めします |
| **複合デバイス**（LAN + カードリーダー + シリアル一体型） | 同様に、同一 USB デバイスの他の機能にも影響します |
| **iPhone の USB テザリング** | Apple 純正の NCM デバイスで、通常は macOS 自身が復旧します。同じ症状が出る場合は本ツールも同様に適用できます |
| **Wi-Fi、Thunderbolt LAN など USB 以外のインターフェース** | 自動的に「ネットワークサービス再起動」にフォールバックします。ソフトウェア層のハングには有効ですが、ドライバ層の停止は解決できません |

お使いの機器が上の表にない場合は、**成否にかかわらず Issue で結果をお知らせください**（機種、`USB VID:PID`、`~/Library/Application Support/LTE Guard/lte-guard.log` の該当部分）。現時点で最も有用な貢献です。

## 「スリープ中も接続を維持」を実装しない理由

初期バージョンにはこの切り替えがありましたが、実測の結果まったく効かないことが判明したため削除しました。理由を記録しておきます。

- **`caffeinate -i -s` では蓋を閉じたスリープを防げません**。`man caffeinate` には `-s` のアサーションが *「システムが AC 電源で動作している場合にのみ有効」* と明記されており、しかも防げるのは**アイドルスリープ**です。**蓋を閉じるのは別の経路（Clamshell Sleep）**であり、caffeinate は介入しません。実際のログでは caffeinate が動作し続けているにもかかわらず、システムは `Entering Sleep state due to 'Clamshell Sleep'` を記録していました。
- **唯一防げるのは `sudo pmset -a disablesleep 1`**（Amphetamine や InsomniaX が用いる手法）ですが、root 権限が必要です。加えて、蓋を閉じたままスリープしないノートを鞄に入れるのは**現実的な発熱リスク**を伴います。
- 判断：本ツールは「復帰後 8 秒で自動復旧する」という 1 点に集中し、特権昇格とハードウェア上のリスクを伴うニッチな用途のために攻撃面を広げないことにしました。

**蓋を閉じたまま接続を維持したい場合**（長時間ダウンロード、無人配信、リモートセッションの維持など）は、[Amphetamine](https://apps.apple.com/app/amphetamine/id937984704)（無料、App Store 掲載）との併用をお勧めします。スリープを防ぐのはあちらに任せ、それでも切れた場合の復旧を本ツールが担当します。

## 既知の制約

- **USB 給電を本当に切ることはできません** —— Apple Silicon の VBUS は SMC ファームウェアが管理しており、公開 API はありません。物理的な電源断が必要な場合は、ポート単位の電源制御（PPPS）に対応した USB ハブと [uhubctl](https://github.com/mvp/uhubctl) を組み合わせてください。
- **Intel Mac** では `USBDeviceReEnumerate` に root 権限が必要な場合があり、ログに `try sudo` と表示されます。
- **ダイヤルアップ型モデム**（ECM/NCM 以外）は再列挙後に再ダイヤルが必要なことがあります。`POST_CMD` をご利用ください。
- 本アプリは Apple の公証を受けていないため、初回起動時は右クリック→開くが必要です。
